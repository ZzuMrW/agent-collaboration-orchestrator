# Agent Collaboration Orchestrator

一个通用的多Agent协作编排框架，支持编排层Agent与执行层Agent的分工协作。

## 概述

本框架实现了一个双层级Agent协作模式：
- **编排层Agent（Orchestrator）**：负责项目整体规划、架构设计、任务分解和质量把控
- **执行层Agent（Executor）**：负责具体代码实现、测试编写和文档生成

## 核心特性

- **智能任务分配**：自动评估任务复杂度，决定由哪层Agent处理
- **清晰的责任边界**：编排层专注设计，执行层专注实现
- **完整的审查流程**：支持多轮迭代和持续审查
- **灵活的沙箱模式**：支持只读、工作区写入、完全访问三种模式

## 安装

将 `SKILL.md` 文件放置到您的技能目录中：

```
your-project/
└── skills/
    └── agent-collaboration-orchestrator/
        └── SKILL.md
```

## 依赖要求

本技能需要配合一个MCP桥接服务使用，该服务需要实现以下接口：

### 必需接口

| 接口名称 | 功能描述 |
|----------|----------|
| `submit_task` | 提交任务给执行层Agent |
| `get_task_status` | 查询任务执行状态 |
| `get_task_log` | 获取任务执行日志 |
| `get_result_report` | 获取任务完成报告 |
| `request_revision` | 请求任务修订 |
| `cancel_task` | 取消正在执行的任务 |
| `list_artifacts` | 列出任务产生的文件 |
| `diagnose_environment` | 诊断环境配置 |

## 使用方法

### 1. 简单任务（编排层直接执行）

适用于：
- 单文件创建/修改（< 50 行）
- 配置文件调整
- 简单查询/信息检索

编排层直接处理，无需调用执行层。

### 2. 中等任务（编排层规划 + 执行层执行）

适用于：
- 多文件修改（2-5 个文件）
- 功能模块实现（100-500 行）
- API 接口开发

```markdown
## 项目背景
实现用户认证模块

## 任务目标
创建JWT认证中间件

## 设计规范
- 文件结构：src/middleware/auth.ts
- 接口定义：verifyToken(req, res, next)
- 数据结构：{ userId: string, role: string }
- 约束条件：使用jsonwebtoken库

## 验收标准
- 功能完整性：验证token、处理过期
- 代码质量：单元测试覆盖率>80%
- 文档要求：API使用文档
```

### 3. 复杂任务（多轮协作）

适用于：
- 新项目创建
- 多模块系统开发
- 跨系统集成

编排层先分解为多个子任务，再逐个提交执行层实现。

## 任务复杂度评估标准

| 复杂度 | 文件数 | 代码行数 | 特征 |
|--------|--------|----------|------|
| 简单 | 1 | < 50 | 单一功能、无依赖 |
| 中等 | 2-5 | 100-500 | 模块级功能、有依赖 |
| 复杂 | > 5 | > 500 | 系统级功能、多模块 |

## 审查检查清单

编排层审查执行层输出时应检查：

- [ ] 架构一致性：是否符合设计架构
- [ ] 接口规范：是否遵循定义的接口
- [ ] 代码质量：是否通过测试、符合规范
- [ ] 文档完整：是否包含必要文档
- [ ] 风险识别：是否有潜在问题

## 示例场景

### 创建Web API项目

**编排层工作：**
1. 设计项目结构（controllers, services, models）
2. 定义API路由和接口规范
3. 制定数据模型和验证规则
4. 分解为子任务

**执行层工作：**
1. 实现路由配置
2. 编写控制器逻辑
3. 实现服务层
4. 编写单元测试

### 代码重构

**编排层工作：**
1. 分析现有代码结构
2. 设计重构目标架构
3. 制定重构步骤
4. 定义约束条件

**执行层工作：**
1. 执行重构
2. 更新测试
3. 生成报告
